The result matches this description: A layered plan, not a single DLP policy. Endpoint DLP rule on the sensitivity labels with the upload-to-restricted-cloud-service-domain activity, Service domains in Allow mode with real host names (no middle wildcards) and a sensitive service domain group for path-level entries, starting in simulation/audit mode. It states, quoting purview/dlp/dlp-configure-endpoint-settings.md, that service domain controls apply only to Edge and to Chrome/Firefox with the Purview extension, so IDEs, dotnet and git are not covered by destination rules (Restricted apps acts on file access only; Global Secure Access network content filtering or a SASE integration is the documented route for app traffic, with its limits). It says the Chrome extension is Windows-only and not needed on macOS, uses tenant restrictions v2 and the OneDrive sync-client tenant allow-list for company-only OneDrive, says DLP cannot tell a personal from a company account on the same SaaS domain, and cites sources with dates.

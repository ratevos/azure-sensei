# Help protect against sharing of a defined set of unsupported files

> Source: https://learn.microsoft.com/en-us/purview/dlp-create-policy-sharing-set-unsupported-files  
> Microsoft doc last updated: 2026-06-26


Create a Microsoft Purview Data Loss Prevention (DLP) policy that helps protect against sharing of a defined set of unsupported files. This article walks you through the configuration steps using the process described in [Design a data loss prevention policy](https://learn.microsoft.com/en-us/purview/dlp-policy-design#design-a-data-loss-prevention-policy). Work through these scenarios in your test environment to familiarize yourself with the policy creation UI.

How you deploy a policy is as important policy design. [This article](https://learn.microsoft.com/en-us/purview/dlp-create-deploy-policy#deploy-and-manage-dlp-policies) shows you how to use the deployment options so that the policy achieves your intent while avoiding costly business disruptions.

Apply controls to some file types is in *preview*.

Use the unsupported file extensions configuration to apply Audit, Block with override, or Block controls to a list of file types only. For example, you can apply controls to video files like .mp3 files (which aren't monitored by endpoint Data Loss Prevention) only.

Important

When you select the **Audit or restrict activities on devices** action in the policy configuration **Actions**, the **Apply restrictions to only unsupported file extensions** shows up. **Apply restrictions to only unsupported file extensions** configuration option ***DOES NOT*** support scoping by **Device and device groups** in the policy location setting.

The following device actions are supported for unsupported file extension restrictions:

- Upload to a restricted cloud service domain
- Copy to a removable USB device
- Copy to a network share
- Print

The unsupported file extensions policy configuration uses a combination of a **File extension group** and the **Document could not be scanned** condition. The unsupported file extensions configuration doesn't use the **File extension is** condition. This policy configuration means that Microsoft Purview endpoint Data Loss Prevention (DLP) doesn't scan the content of the files that you include in the **File extension group** and you don't see values for **Sensitive info type** in events or alerts that are generated by policy matches.

Important

This article presents a hypothetical scenario with hypothetical values. It's only for illustrative purposes. Substitute your own sensitive information types, sensitivity labels, distribution groups, and users.

## Policy intent statement and mapping

*We, Wingtip Toys, have a list of file types on devices which are NOT on the monitored files list and that we want to apply controls to. We know that they're not on the monitored files list for Endpoint DLP. We want to prevent users from copying those files to a USB device or to a network share. When they do try, we want to let them know, to educate them, that they are attempting a prohibited action.*

## Steps to create a file extension group

The following steps use the Microsoft Purview portal. To learn more, see [Microsoft Purview portal](https://learn.microsoft.com/en-us/en-us/purview/purview-portal).

1. Sign in to the [Microsoft Purview portal](https://purview.microsoft.com).
2. Open **Settings** &gt; **Data Loss Prevention** &gt; **Endpoint DLP settings** &gt; **File extension groups**.
3. Select **Create file extension group** and enter a **Group name**. In this scenario, use `Non-classified file extensions`.
4. Provide extensions.
5. Select **Save**.
6. Close the item.

## Steps to configure policy actions

Perform the following steps to configure the policy actions for this scenario.

1. Sign in to the [Microsoft Purview portal](https://purview.microsoft.com).
2. Open **Data Loss Prevention** &gt; **Policies**.
3. Select **Create policy**.
4. Select **Enterprise applications & devices**.
5. Select **Custom** from the **Categories** then select **Custom policy** template from **Regulations**.
6. Name your new policy and provide a description.
7. Select **Full directory** under **Admin units**.
8. Scope the location to **Devices** only.
9. Create a rule where:
    1. In **Conditions**.
        1. **Document could not be scanned**.
    2. In **Actions**:
        1. Select: **Audit or restrict activities on devices**.
        2. Clear: **Upload to a restricted cloud service domain or access from an unallowed browser**.
        3. Select: **Apply restrictions to specific activity**.
        4. Clear: **Copy to clipboard**.
        5. Select: **Copy to a removable USB device** &gt; **Block**.
        6. Select: **Copy to a network share** &gt; **Block**.
        7. Clear: **Print**.
        8. Clear: **Copy or move using unallowed Bluetooth app**.
        9. Clear: **Copy or move using RDP**.
        10. Clear: **Access by restricted apps**.
        11. Select: **Apply restrictions to only unsupported file extensions**.
        12. Select: **Add file extension group** and select `Non-classified file extensions`.
10. Set **User notifications** to **On**.
    1. Under **Endpoint devices** select **Show users a policy tip notification when an activity is restricted...**.
    2. Select **Customize the notification**.
        1. Enter `Wingtip toys don't copy files` in the **Notification Title**.
        2. Enter `FYI, Wingtip Toy policy doesn't let you copy that type of file to USB device or a network share` in the **Notification Content**.
11. **Save**.
12. Choose **Turn the policy on immediately**. Choose **Next**.
13. Review your settings and choose **Submit**.

Important

You can't use the **Document could not be scanned** condition with other conditions in this scenario.
